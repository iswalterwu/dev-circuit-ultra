# dev-circuit-ultra：框架级功能

只在功能命中 SKILL.md "开工"一节的框架级条件时读；普通功能用不到本文件。框架级在四步循环之上多做下面这些。

## 设计（① 里，点头前）

1. 问意图和设计约束：一次一个问题，只问会改变结构或边界的，通常不超过 3 轮。
2. 给 2–3 个结构 / 行为方案，写清各自取舍，推荐一个，让用户选。方案只在对话里出现；选定后只写选中的方案，被否方案不落盘。
3. 改能力规格、写意图卡，再按 `templates/design.md` 写 `specs/<feature>/design.md`：只写现行结构、边界、契约和现行理由。
4. 构建者检查：假设要按这份设计动手、却联系不上作者，列出猜错会造成实质影响的问题。文档里已有答案的，补进文档；小问题自己定，在文档里标"我的判断"；只能用户定的，点头时一起问。
5. 点头时连同 `design.md` 一起确认，并提一句可以加一次结构审（`reviewer.md` 的结构审模式），由用户定。

## 第一个切片：骨架切片

打通一条贯穿所有模块、覆盖风险最高路径的最细端到端路径。内部可以用桩，但模块之间的连线和契约测试必须是真的。

## 收尾（最后一个切片）

把 `design.md` 里仍然有效的结构、边界和关键决定并入 `docs/architecture.md`（每个关键决定可以附一句现行理由），在 `docs/README.md` 登记；`design.md` 随功能目录一起删除。
